# Reliability alpha release checklist

`tests/acceptance/alpha-matrix.md` is the binding acceptance matrix. The private qualification command must reject zero/skipped automation, missing signoff, a run below the authorized 6-hour soak, shortened seven-day trial or evidence for different source/artifact hashes. Source owner and maintenance/security contacts remain public-distribution requirements; they do not block private qualification.

1. Confirm exact source/toolchain/artifact identity and exclusive test fixture ownership. Preserve the active demo. Run the complete current-source suite and inspect both Simulator layouts and actual browser interaction.
2. Verify reload/retry, capacity/storage, restore/migration, app lifecycle and consent regressions. Run packaged desk installation, reproducible two-build comparison and public-interface SDK consumption. Test app update over a preserved install.
3. Obtain the confirmed real Linux ARM64 test ship, trusted HTTPS/renewal/ingress and recovery path. Complete install/update/latency/loss/capacity, actual-backup operator rehearsals, 6-hour soak and independent auth/storage review.
4. Have an unfamiliar developer create a distinct schema from the docs without an SDK fork/copied TodoStore/staff enrollment. Complete 2–3 owner/developer testers’ seven-day practical use and in-place update/offline recovery. Record setup time separately from first save/round trip.
5. Preserve complete upstream notices and MIT attribution. Reconcile every technical input and sanitized evidence file against the final manifest. Fix integrity/authority findings and rerun affected qualification before declaring the private alpha qualified.
6. Prepare the local desk/SDK/Todo source bundle. If publication is separately authorized, resolve source ownership and maintainer/security contacts, confirm exact channels/publisher identity and test clean retrieval/install. Otherwise report a local candidate and pending distribution; do not call it public or qualified while required gates remain.

No Apple membership/TestFlight, physical-device qualification, publisher registry, companion app or central data server is introduced to finish this milestone.
