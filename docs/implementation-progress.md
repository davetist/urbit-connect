## SDK coordination design carried between contexts

- Implemented `ConnectClient` as the sole owner of a synchronous LocalStore; internal injectable transport/clock/token store and `automaticallySync:false` support deterministic unit tests. The original failing test stub was replaced with the implementation recorded below.
- Account/cache/Keychain key = SHA-256 of issuer, instance, client with explicit separators. Persist only a selected-key pointer outside Keychain. Reauthorization of the same account and epochs keeps exact outbox bodies; changed global/namespace epochs mark drafts needs-attention, clear confirmed data/cursor, and never replay old requests. Explicit pairing to a new account opens a separate database.
- Each queued mutation has exact body bytes, expected revision, created date, status, optional dependency, and optional acknowledged revision. Writes while an earlier document write is in flight create a dependent draft. After the parent's durable acknowledgement and delta/snapshot application, atomically remove it and prepare dependent bytes against the acknowledged revision. A concurrent remote edit then causes CAS conflict, never silent rebasing onto remote data.
- One sync loop does snapshot/deltas, sends eligible outbox entries, and long-polls. A new local edit cancels only the pending long-poll child task, not an in-flight mutation. A generation UUID plus cancellation checks after every await prevent an old account/task response from writing into a new account cache.
- Before refresh POST, durably write `refreshInFlight=true` in Keychain. Serialize refresh through one shared task. Persist the rotated pair before clearing the flag. An ambiguous refresh or process death with this flag requires reauthorization; never resend the old refresh token. A definite revoked session clears confirmed cache/credentials and retains only recoverable unsent user drafts (clear any stored remote conflict body).
- Snapshot pages install once in a single SQLite transaction after completion; expired snapshots restart, journal gaps re-snapshot without discarding drafts. Receipts acknowledged before response loss retry exact bytes. Pending mutations older than 30 days require explicit reconciliation. Permanent 4xx stop retrying that draft. Offline network errors retain drafts and use bounded backoff.
- Public API includes original plan methods plus resume/foreground control, recoveryDrafts and explicit conflict resolution needed by the sample. Keep owner cookies out of URLSession/SDK and use the system auth presenter. HTTP response bounds should be enforced while reading if practical, not solely after allocation.
