# Installing the alpha desk

Historical reference-host validation used a dedicated test comet: Raspberry Pi 4 Model B Rev 1.4, 8 GiB, Linux ARM64, Vere 4.6 and Zuse 408. A fresh 0.1.0 installation followed by 0.2.0-alpha.1 passed trusted HTTPS, bundled-manager and grant/document/receipt preservation checks. These are historical observations; timed trials, soaks and independent signoffs are no longer release gates. See `supported-platforms.md` and the final alpha report.

Prepare a verified stopped-pier backup and record its checksum and recovery point privately. Inspect installed desks and refuse an unrelated existing `%connect` desk; do not replace another publisher’s desk. Check free disk/RAM, the runtime’s stable release, Kelvin support and the artifact SHA-256 against the supplied manifest. Runtime/pier upgrades are separate operations; never apply the Mac development LMDB workaround automatically on Linux.

The local `dist/connect-0.2.0-alpha.1.tgz` contains a `connect/` desk, its file manifest and third-party notices. Inspect/extract only bounded regular files, reject absolute/traversal/link entries, and verify every desk file hash before copying. In an authorized test ship create and mount the new desk with `|new-desk %connect` and `|mount %connect`, copy the verified desk directory into that mount, `|commit %connect`, and `|install our %connect`. The package verifier rehearses this on a fresh owned fake pier. Check the actual UI and `/connect/v1/info` after installation; a successful Dojo command is insufficient.

Supply HTTPS before configuring the issuer. The tested profile uses Tailscale Serve HTTPS on 8443 to a loopback Caddy 2.11.7 listener, then loopback Eyre. `operations/tailscale-reference.Caddyfile` records that private proxy configuration; [Serve manages HTTPS certificates and exposes the service within the tailnet](https://tailscale.com/docs/features/tailscale-serve). Only tailnet-authorized clients can reach this profile. The general public-domain `operations/reference.Caddyfile` is an unqualified alternative. Do not expose a fake ship or its acceptance-control service. A provider refusing custom desks is unsupported.

Run `python3 scripts/doctor.py https://your-ship.example` without disabling TLS. Verify the asserted ship/instance against the selected target and configure the origin in the owner manager. This endpoint identity is not an independently verified Urbit identity. Register the sample explicitly, then complete Todo/manager consent, CRUD and revocation checks.

Keep the verified backup, exact archive, hashes and install evidence. The current distribution channel and source owner/contact are pending. Authentic notices and the Landscape-source comparison are included; no public publishing ship is invented by these instructions.

`scripts/real_install.py` is a guarded helper for the already prepared connect-dev experiment, not a general host provisioner. It checks the exact recorded ship/pier, private Eyre binding and verified Harbor backup, rejects unsafe/unmanifested archive files or a live base/desk Kelvin other than 408, and requires at least 1 GiB plus twice the staged desk size free before writing. This refusal threshold is not a measured minimum host size. Missing ownership markers, an unrelated desk, partial setup and unsupported runtime require investigation before installation; the helper never creates a replacement personal ship.
