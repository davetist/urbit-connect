# Installing the desk

Historical reference-host validation used a dedicated test comet: Raspberry Pi 4 Model B Rev 1.4, 8 GiB, Linux ARM64, Vere 4.6 and Zuse 408. A fresh 0.1.0 installation followed by 0.2.0-alpha.1 passed trusted HTTPS, bundled-manager and grant/document/receipt preservation checks. These are historical observations; timed trials, soaks and independent signoffs are no longer release gates. See `supported-platforms.md` and the final alpha report.

Inspect installed desks and refuse an unrelated existing `%connect` desk; do not replace another publisher’s desk. Check free disk/RAM, the runtime’s stable release, Kelvin support and the artifact SHA-256 against the supplied manifest. A stopped-pier copy is not a rollback plan for a ship that will continue running. Runtime/pier upgrades are separate operations; never apply the Mac development LMDB workaround automatically on Linux.

The local `dist/connect-0.2.0.tgz` contains a `connect/` desk, its file manifest and third-party notices. Inspect/extract only bounded regular files, reject absolute/traversal/link entries, and verify every desk file hash before copying. On an authorized ship create and mount the new desk with `|new-desk %connect` and `|mount %connect`, copy the verified desk directory into that mount, `|commit %connect`, and `|install our %connect`. The package verifier rehearses this on a fresh owned fake pier. Check the actual UI and `/connect/v1/info` after installation; a successful Dojo command is insufficient.

Supply trusted HTTPS before configuring the issuer. Eyre may terminate TLS itself, or an existing trusted ingress may forward to Eyre. One tested private profile used Tailscale Serve HTTPS on 8443 through loopback Caddy to loopback Eyre; `operations/tailscale-reference.Caddyfile` records that configuration. [Tailscale Serve](https://tailscale.com/docs/features/tailscale-serve) restricts that profile to tailnet-authorized clients. The reference Caddyfiles are examples, not requirements. Do not expose a fake ship or its acceptance-control service. A provider refusing custom desks is unsupported.

Run `python3 scripts/doctor.py https://your-ship.example` without disabling TLS. Verify the asserted ship/instance against the selected target and configure the origin in the owner manager. This endpoint identity is not an independently verified Urbit identity. Register the sample explicitly, then complete Todo/manager consent, CRUD and revocation checks.

Keep the exact archive, hashes and install evidence. Authentic notices and the Landscape-source comparison are included. Published desk names and their publisher should be confirmed from the release announcement before installation.

`scripts/real_install.py` is a guarded helper for the already prepared connect-dev experiment, not the stable main-ship installation path or a general host provisioner. It checks that test ship's exact recorded identity/pier, private Eyre binding and Harbor archive, rejects unsafe/unmanifested archive files or a live base/desk Kelvin other than 408, and requires at least 1 GiB plus twice the staged desk size free before writing. This refusal threshold is not a measured minimum host size. Missing ownership markers, an unrelated desk, partial setup and unsupported runtime require investigation before installation; the helper never creates a replacement personal ship.
